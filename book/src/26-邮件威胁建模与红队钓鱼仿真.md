# 第二十六章：邮件威胁建模与红队钓鱼仿真

> 本章从红队视角出发，系统化拆解邮件系统的攻击面建模、钓鱼仿真工具链（GoPhish）与 MFA 绕过技术（Evilginx2），帮助安全团队建立"以攻促防"的实战能力。

## 26.1 邮件威胁建模方法论

### 26.1.1 STRIDE 模型在邮件系统中的映射

| STRIDE 类别 | 邮件系统攻击向量 | 典型场景 |
|------------|----------------|---------|
| **S**poofing（身份伪造） | SMTP 信封伪造、Lookalike Domain、Display Name Spoofing | `ceo@company.com` → `ceo@cornpany.com`（r→rn 混淆） |
| **T**ampering（数据篡改） | 中间人 TLS 降级、MTA 队列注入、Webmail XSS 改信 | 恶意 .ics 覆盖已有日历事件 |
| **R**epudiation（抵赖） | SMTP 日志篡改、发送行为否认 | 内网用户通过匿名 SMTP 发送泄密邮件 |
| **I**nformation Disclosure | Autodiscover 凭据泄露、Eml 文件头信息泄漏 | `autodiscover.xml` 回退到攻击者控制的服务器 |
| **D**enial of Service | SMTP 连接耗尽、Zip Bomb 附件解压炸弹、邮件炸弹（Mail Bomb） | 单一邮箱 10 万封入站队列溢出 |
| **E**levation of Privilege | Sieve 规则提权、Inbox Rule 持久化、SASL 凭据喷射 | 恶意 IMAP 客户端创建隐蔽转发规则 |

### 26.1.2 MITRE ATT&CK 邮件相关技术映射

- **T1566 — Phishing**（钓鱼）：Spearphishing Attachment / Link / via Service
- **T1078 — Valid Accounts**（有效凭据）：BEC 诈骗中利用被盗邮箱凭据
- **T1534 — Internal Spearphishing**（内部钓鱼）：已攻陷邮箱用于组织内部横向扩散
- **T1098 — Account Manipulation**（账户操纵）：添加邮箱转发规则、额外邮箱别名
- **T1114 — Email Collection**（邮件收集）：IMAP/POP3 拖取全量历史邮件
- **T1048 — Exfiltration Over Alternative Protocol**（替代协议外传）：通过 SMTP 外传敏感数据

### 26.1.3 攻击链（Kill Chain）建模

```text
侦察 → 武器化 → 投递 → 利用 → 安装 → C2 → 目标达成
  │       │       │      │      │     │       │

  │   恶意.ics  投递    │ 附件    │  规则   │  窃取
  │   钓鱼链接         │ 漏洞    │  持久化  │

```

## 26.2 红队钓鱼仿真平台：GoPhish

### 26.2.1 GoPhish 架构与部署

- Go 语言编写，单二进制部署，内置 Web 管理面板
- 核心组件：Campaign（活动管理）、Landing Page（钓鱼页面）、Email Template（邮件模板）、Sending Profile（SMTP 配置）
- Docker Compose 一键部署，结合 Nginx 反代 + LetsEncrypt 证书规避安全软件标记

### 26.2.2 钓鱼邮件模板设计技巧

- **绕过网关 SPF/DKIM 检测**：使用与目标域相似的"同级域"（Sibling Domain）发送，而非直接伪造
- **HTML 躲避技术**：零宽字符插入品牌名、CSS `display:none` 隐藏反垃圾文本段
- **动态重定向**：GoPhish 的 `{{.URL}}` 追踪令牌与 `{{.Tracker}}` 像素统计
- **日历邀约钓鱼**：通过 .ics 附件注入 GoPhish 追踪链接，绕过邮件正文网关检测

### 26.2.3 钓鱼演练的合规边界与道德准则

- 明确用户知情权与演练后通知/培训义务
- 敏感部门的排除规则（财务/高管是否需要独立审批）
- 数据最小化：只记录点击率，不收集密码明文（密码应走假登录页 `action="#"`）

## 26.3 MFA 多因子认证绕过实战：Evilginx2

### 26.3.1 Evilginx2 的原理：反向代理中间人（AiTM）

- Evilginx2 不是密码窃取器——它是 **反向代理中间人**
- 用户 → Evilginx2（TLS 终结）→ 真实登录服务（M365/Gmail/OWA）
- 当用户完成 MFA 后，Evilginx2 在中间截获**已认证的 Session Cookie**
- 攻击者利用这个 Session Cookie 以用户身份直接登录，**完全绕过 MFA**

### 26.3.2 Phishlet 机制与邮件系统场景适配

- Phishlet 是 Evilginx2 的"目标配置模板"（YAML 格式），定义登录页的 URL 匹配规则、凭据字段、Session Cookie 名称
- 邮件系统 Phishlet 适配：
  - **Microsoft 365 / Exchange OWA**：`owa.phishlet` → 劫持 `ESTSAUTHPERSISTENT` / `SignInCookies`
  - **Gmail / Google Workspace**：`gmail.phishlet` → 劫持 `SIDCC` / `__Secure-3PSID`
  - **Zimbra Web Client**：自定义 `zimbra.phishlet` → 劫持 `ZM_AUTH_TOKEN`
  - **Roundcube / SnappyMail**：劫持 `roundcube_sessid` / `snm_*`

### 26.3.3 Evilginx2 的防御检测与对抗

- **证书透明度（CT）日志监控**：检测攻击者为 phishing 域签发的 SSL 证书
- **TLS 指纹（JA3/JA4）**：Evilginx2 的 Go TLS 库指纹与真实浏览器不同
- **域名新注册检测**：Evilginx2 依赖新注册的 Lookalike Domain，whois 新鲜度是强信号
- **CNAME Cloaking**：攻击者利用 Cloudflare/CDN 隐藏真实 IP 的对策

## 26.4 实战：红队全链路钓鱼攻击模拟

### 26.4.1 场景：针对某企业邮件系统的全链路测试

1. **侦察**：LinkedIn 爬取员工组织架构 → Hunter.io 验证邮箱格式 → `dig MX` 确认 MTA
2. **武器化**：制作"IT 部门密码重置通知"HTML 邮件模板 → Evilginx2 部署 `owa.phishlet` → GoPhish 配置 SMTP Sending Profile
3. **投递**：GoPhish 分批发送（每批 50 人，间隔 15 分钟，避免触发速率限制）
4. **利用**：Evilginx2 截获 Session Cookie → 攻击者登录 OWA → 创建隐蔽的 Inbox Rule（所有邮件 BCC 到外部邮箱）
5. **持久化**：注册新的 MFA 设备 / 添加 OAuth 应用权限
6. **数据外传**：IMAP 逐封拖取发件箱+收件箱历史邮件

### 26.4.2 红队测试的攻防双方交付物

**红队交付物：**
- 钓鱼点击率统计（分部门/职级/时间窗口）
- Evilginx2 Session 捕获报表（含 MFA 类型分布）
- 成功持久化的 Inbox Rule / OAuth App 清单
- 横向移动可达路径

**蓝队防御检查清单（对应本章知识）：**
- [ ] 是否监控 Autodiscover 回退请求的异常 DNS 查询？
- [ ] 是否有 Lookalike Domain 注册的自动化告警（DNSTwist）？
- [ ] MTA-STS / DANE 是否已启用，防止 SMTP TLS 降级？
- [ ] OWA 登录是否强制 FIDO2/WebAuthn（抗 Evilginx2 AiTM）？
- [ ] Inbox Rule 创建是否有审计日志与异常规则告警？
- [ ] 是否实施全局 DMARC `p=reject` 策略？
- [ ] 员工是否接受过针对日历邀约钓鱼的专项安全培训？
